# منصة التقييمات

أداة بسيطة تبني بها الأدمن طلب تقييم لكل عميل بعد شرائه، ترسله له كرابط
خاص، تراجع وتعتمد أو ترفض التقييمات الواردة، ثم تعرض المعتمد منها في
صفحة عامة.

## الأقسام

- **`/`** — صفحة رئيسية بسيطة.
- **`/reviews`** — ويدجت عام يعرض التقييمات المعتمدة فقط.
- **`/review/[token]`** — الصفحة اللي يفتحها العميل من الرابط اللي ترسله له
  ليقيّم تجربته (مرة وحدة فقط لكل رابط).
- **`/admin/[secret]`** — لوحة التحكم: إنشاء طلبات تقييم جديدة، مراجعة
  واعتماد/رفض التقييمات الواردة، وإحصائيات سريعة. **ما فيها تسجيل دخول** —
  الوصول عن طريق التوكن السري نفسه في الرابط (`ADMIN_ACCESS_TOKEN`)، فحافظ
  عليه ولا تشاركه إلا مع من تثق فيه.

## الإعداد

### 1) قاعدة البيانات

روح لمشروعك في [Supabase](https://supabase.com) → SQL Editor، والصق محتوى
ملف [`supabase/schema.sql`](./supabase/schema.sql) كامل واضغط Run. هذا ينشئ
جدول `reviews`، سياسات RLS، والدوال اللي تحتاجها الصفحات العامة.

### 2) متغيرات البيئة

انسخ `.env.example` إلى `.env.local` وعبّي القيم:

```bash
cp .env.example .env.local
```

- `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`: من
  Project Settings → API في Supabase.
- `SUPABASE_SERVICE_ROLE_KEY`: من نفس الصفحة (**سري، لا يظهر في المتصفح
  أبدًا** — يُستخدم فقط داخل السيرفر للوحة التحكم).
- `ADMIN_ACCESS_TOKEN`: قيمة عشوائية طويلة تختارها أنت، مثلاً بالأمر:

  ```bash
  openssl rand -hex 32
  ```

  رابط لوحة التحكم بعدها يصير: `https://your-domain.com/admin/<القيمة-هذي>`

### 3) التشغيل محليًا

```bash
npm install
npm run dev
```

### 4) النشر

يشتغل مباشرة على [Vercel](https://vercel.com) — اربط المستودع وحط نفس
متغيرات البيئة في إعدادات المشروع هناك.

## ملاحظات أمنية

- لوحة التحكم محمية برابط سري بس (بدون تسجيل دخول)، فلا تنشر التوكن في أي
  مكان عام، ولو انكشف بدّله فورًا في Supabase والـ env vars.
- مفتاح `service_role` يتجاوز كل الحمايات (RLS) — يُستخدم فقط في أكواد
  السيرفر (Server Actions) ولا يوصل للمتصفح إطلاقًا.
- صفحات `/admin` و `/review` محجوبة عن الفهرسة (`robots.txt` + `noindex`)
  حتى ما تنكشف روابطها عن طريق محركات البحث.
