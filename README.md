# منصة التقييمات

هذا المستودع فيه مشروعين منفصلين تمامًا بقاعدة بيانات واحدة (Supabase)،
بس بجداول مختلفة لكل واحد، صفر تشارك بالبيانات بينهم:

1. **لوحة شامل بلس الخاصة** (`/admin`) — أداة داخلية لمتجر shamelplus.com
   بس، بتسجيل دخول مقفل على إيميلين محددين.
2. **المنصة العامة** (`/signup`, `/dashboard`, `/u/[slug]`) — أي بائع
   (حتى بدون متجر، مثل البيع عبر تيليجرام) يسجل حساب مجاني ويحصل على
   نظام تقييمات خاص فيه + صفحة عامة يشاركها كمرجع لثقة عملائه.

## 1) لوحة شامل بلس الخاصة

- **`/`** — صفحة رئيسية.
- **`/reviews`** — صفحة عامة تعرض تقييمات شامل بلس المعتمدة فقط.
- **`/widget.js`** + **`/api/reviews`** — ويدجت جافاسكربت تُلصق بموقع
  شامل بلس لعرض نفس التقييمات مباشرة بصفحاته (تفاصيل تحت في قسم
  "عرض التقييمات بالمتجر").
- **`/review/[token]`** — الصفحة اللي يفتحها عميل شامل بلس من الرابط اللي
  ترسله له ليقيّم تجربته (مرة وحدة فقط لكل رابط).
- **`/admin`** — لوحة التحكم: إنشاء طلبات تقييم جديدة، مراجعة واعتماد/رفض
  التقييمات الواردة، وإحصائيات سريعة. محمية بتسجيل دخول حقيقي عبر
  Supabase Auth، ومقتصرة على الإيميلات المذكورة في `ADMIN_ALLOWED_EMAILS`
  فقط — حتى لو أنشأت حساب Supabase Auth ثاني، ما يقدر يدخل إلا لو
  إيميله مضاف لهذه القائمة.
- **`/admin/customers`** — قائمة العملاء (بحث بالاسم أو رقم الجوال) وكل
  عميل له صفحة (`/admin/customers/[id]`) تعرض تاريخه الكامل من طلبات
  التقييم، وفيها نموذج تسوي منه طلب تقييم جديد له مباشرة بضغطة وحدة.
  المطابقة بين طلبات التقييم لنفس العميل تتم عن طريق رقم الجوال.

## 2) المنصة العامة (متعدد البائعين)

- **`/signup`** — تسجيل حساب جديد: اسم النشاط، رابط عام مخصص (`/u/<رابط>`)،
  بريد وكلمة سر. تسجيل ذاتي مفتوح للكل، بدون موافقة مسبقة.
- **`/login`** — تسجيل دخول لأي حساب بائع.
- **`/dashboard`** — لوحة تحكم البائع: نفس مزايا لوحة شامل بلس (إنشاء
  طلبات، مراجعة واعتماد/رفض، عملاء وتاريخهم) بس مقصورة على بياناته هو بس.
- **`/dashboard/customers`** + **`/dashboard/customers/[id]`** — نفس فكرة
  عملاء شامل بلس، لكل بائع عملاؤه الخاصين.
- **`/u/[slug]`** — الصفحة العامة اللي يشاركها البائع مع عملائه (بايو
  تيليجرام، توقيع واتساب، إلخ) — تعرض تقييماته المعتمدة فقط.
- **`/r/[token]`** — الصفحة اللي يفتحها عميل أي بائع من المنصة العامة
  ليقيّم تجربته (مقابل `/review/[token]` الخاص بشامل بلس).

## الإعداد

### 1) قاعدة البيانات

روح لمشروعك في [Supabase](https://supabase.com) → SQL Editor، والصق محتوى
ملف [`supabase/schema.sql`](./supabase/schema.sql) كامل واضغط Run. هذا ينشئ
جداول `customers` و`reviews` (لوحة شامل بلس)، سياسات RLS، والدوال اللي
تحتاجها الصفحات العامة.

> **عندك مشروع شغّلت فيه `schema.sql` قبل؟** شغّل بعده ملف
> [`supabase/migrations/002_customers.sql`](./supabase/migrations/002_customers.sql)
> — يضيف جدول العملاء بدون ما يمس أي بيانات موجودة.

بعدها شغّل ملف
[`supabase/migrations/003_multi_tenant.sql`](./supabase/migrations/003_multi_tenant.sql)
— ينشئ جداول `merchants`, `merchant_customers`, `merchant_reviews`
الخاصة بالمنصة العامة، منفصلة تمامًا عن جداول شامل بلس.

بعد تشغيل ملف 003، روح لـ **Authentication → Providers → Email** وعطّل
**"Confirm email"** — عشان التسجيل الذاتي بـ `/signup` يصير فوري بدون
انتظار إيميل تأكيد (إلا إذا كان عندك SMTP حقيقي مُعد، وقتها سيبها مفعّلة).

### 2) متغيرات البيئة

انسخ `.env.example` إلى `.env.local` وعبّي القيم:

```bash
cp .env.example .env.local
```

- `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`: من
  Project Settings → API في Supabase.
- `SUPABASE_SERVICE_ROLE_KEY`: من نفس الصفحة (**سري، لا يظهر في المتصفح
  أبدًا** — يُستخدم فقط داخل السيرفر للوحة التحكم).
- `ADMIN_ALLOWED_EMAILS`: إيميلات المشرفين المسموح لهم بدخول `/admin`،
  مفصولة بفاصلة.

### 3) إنشاء حسابات المشرفين

اللوحة تسجيل دخول حقيقي (بريد + كلمة سر) عبر Supabase Auth، مو رابط سري.
أسهل طريقة تنشئ الحسابات:

```bash
cp scripts/admins.example.json scripts/admins.local.json
# عدّل الملف بإيميلات وكلمات سر المشرفين الفعليين (هذا الملف مستثنى من git)
npm run create-admins
```

بديل بدون سكربت: من لوحة Supabase مباشرة، Authentication → Users → Add
user، وفعّل "Auto Confirm User" حتى يقدر يدخل فورًا بدون تأكيد إيميل.

في الحالتين، لا تنسى تضيف نفس الإيميلات في `ADMIN_ALLOWED_EMAILS` — بدونها
الحساب يقدر يسجل دخول في Supabase لكن يُرفض من التطبيق.

### 4) التشغيل محليًا

```bash
npm install
npm run dev
```

### 5) النشر

يشتغل مباشرة على [Vercel](https://vercel.com) — اربط المستودع وحط نفس
متغيرات البيئة في إعدادات المشروع هناك.

## عرض التقييمات بالمتجر

### الطريقة الأبسط — تلقائي فوق الفوتر

ألصق سطر واحد بس بأي مكان بالصفحة (حتى بمنطقة "أكواد إضافية" العامة):

```html
<script src="https://<دومين-مشروعك>/widget.js" defer></script>
```

الويدجت يدوّر تلقائيًا على الفوتر بالصفحة ويحط نفسه فوقه مباشرة، بعنوان
"آراء عملائنا" وتصميم جاهز (نجوم + اسم + تعليق) — بدون أي إعداد إضافي.

### أو تحديد المكان بنفسك

لو تبي التقييمات بمكان معيّن (تحت وصف منتج مثلًا)، حط `div` بنفسك وقتها
الويدجت يستخدمه بدل البحث عن الفوتر:

```html
<div data-t1yyemat-reviews></div>
<script src="https://<دومين-مشروعك>/widget.js" defer></script>
```

خيارات اختيارية على نفس الـ `div`:

```html
<div data-t1yyemat-reviews data-limit="6" data-product="اسم المنتج"></div>
```

- `data-limit`: أقصى عدد تقييمات تظهر (افتراضي 20).
- `data-product`: يعرض تقييمات منتج واحد بس (لازم يطابق `اسم المنتج` اللي
  كتبته وقت إنشاء طلب التقييم بالضبط).

## ملاحظات أمنية

- الدخول للوحة التحكم مقفل على طبقتين: تسجيل دخول صحيح في Supabase Auth
  + الإيميل موجود في `ADMIN_ALLOWED_EMAILS`. غيّر القائمة وقت ما تحتاج
  تضيف أو تشيل مشرف — بدون أي تعديل بالكود.
- مفتاح `service_role` يتجاوز كل الحمايات (RLS) — يُستخدم فقط في أكواد
  السيرفر (Server Actions) ولا يوصل للمتصفح إطلاقًا.
- `scripts/admins.local.json` فيه كلمات سر فعلية — لا تلصقه في أي مكان
  عام ولا ترفعه لأي مستودع (مستثنى من git تلقائيًا).
- صفحات `/admin` و `/review` محجوبة عن الفهرسة (`robots.txt` + `noindex`)
  حتى ما تنكشف روابطها عن طريق محركات البحث.
- حسابات المنصة العامة مفصولة تمامًا عن بيانات شامل بلس — ما فيه جدول
  أو عمود مشترك بينهم، وكل استعلام بلوحة `/dashboard` مقيّد بـ
  `merchant_id` تابع للجلسة الحالية، يتحقق منه كل Server Action بنفسه.
- صفحات `/dashboard` و `/r` محجوبة عن الفهرسة بنفس طريقة `/admin` و`/review`.
